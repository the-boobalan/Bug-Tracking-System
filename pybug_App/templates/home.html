Bug Lifecycle

From Open to Closed — Nothing Slips

Every bug follows a strict, trackable 5-stage lifecycle. Visibility at every step, for every role.

1
Open
Reported, awaiting triage
2
Assigned
Dev picked up the issue
3
Resolved
Fix submitted for review
4
Verified
QA confirmed the fix
5
Closed
Bug fully resolved
🔴
Open

Bug reported and logged. Awaiting manager assignment to a developer.

🟡
Assigned

Developer notified and actively working on reproducing and fixing the issue.

🔵
Resolved

Fix committed. Awaiting tester verification before the ticket closes.

🟣
Verified

Tester confirmed fix works as expected. Manager can now close the bug.

🟢
Closed

Bug officially closed. Archived in project history for audit and reference.

Priority System

Triage With Precision

Every bug gets a severity tag so your team always knows what to tackle first.

P0 · Critical 🔴
System-Breaking Issue

Core functionality is blocked. Production is affected. Requires immediate developer attention with zero tolerance for delay.

SLA: Same Day
P1 · High 🟠
Major Functionality Degraded

Users experience significant friction. Important features are impacted. Must be resolved within the current sprint.

SLA: 3 Days
P2 · Medium 🔵
Non-Critical with Workaround

Issue exists but users can work around it. Scheduled for the next sprint without urgent pressure on the team.

SLA: Next Sprint
P3 · Low 🟢
Minor / Cosmetic

Minimal user impact. UI polish, copy fixes, or edge-case behavior. Addressed as bandwidth allows in future iterations.

SLA: Backlog
Team Roles

  • Manage all users & roles
  • Create & delete projects
  • View all system reports
